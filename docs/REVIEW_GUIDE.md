# 作品操作與程式碼閱讀指南

這份指南提供面試、接案或 GitHub review 時可直接重現的流程。資料保存在目前瀏覽器，請使用虛構姓名、Email 和測試地址。

## 建議的三條操作路線

| 路線            | 操作入口                                                | 檢查重點                                                       |
| --------------- | ------------------------------------------------------- | -------------------------------------------------------------- |
| 電商 → 訂單處理 | `shop.html` → `dashboard.html#orders`                   | 配送欄位、地址連動、優惠與加價購、庫存檢查、訂單快照、狀態紀錄 |
| 合約 → 入庫     | `dashboard.html#contracts` → `#receiving` → `#activity` | 狀態轉移、退回原因、良品數量、避免重複入庫、操作紀錄           |
| 訊息 → 狀態     | `messages.html`                                         | 未讀、封存、逐批載入、事件重送去重、離線與取消訂閱             |

## 電商與後台

1. 在 AXIS 加入一個保溫隨行杯，開啟購物車並繼續結帳。
2. 選擇城市及行政區，再換城市：行政區應重設，不能沿用不相容的值。
3. 切換宅配和超商取貨：地址與 6 位數門市代碼使用不同驗證。
4. 套用 `AXIS10` 並勾選 NT$ 290 加價購。單件隨行杯 NT$ 1,280，折抵 NT$ 128，宅配 NT$ 100，總額 NT$ 1,542。
5. 使用虛構資料建立本機訂單。到後台「訂單管理」，搜尋該訂單，開啟詳情。
6. 核對收件資料、加價購標記、折扣、運費及總額。這些是下單快照。
7. 將待處理改為處理中，再改為已完成。詳情應保存兩筆狀態變更；已完成不再提供後續狀態。
8. 篩選訂單後「匯出目前結果」：只匯出符合條件的訂單。

舊樣本訂單只有總額，沒有配送及費用拆分；詳情會明確說明。狀態變更只記錄流程，不執行付款、退款、通知或庫存回補。

## 商務流程

1. 新增合約，調整數量、月數與每件月費，觀察總額。
2. 退回時不填原因會被阻擋；填寫原因後退回，再修改重送。
3. 到商家入庫：以預計 10 件為例，實收 10 件、損壞 1 件，必須填寫原因；良品為 9 件。
4. 完成後到商品庫存核對增加 9 件，入庫單無法重複完成。
5. 操作紀錄可以按編號、動作與備註搜尋。它是本機紀錄，不是不可竄改的伺服器稽核。

## 訊息處理

1. 開啟一則未讀訊息，觀察未讀數減少。
2. 封存後到已封存區，再移回收件匣。
3. 捲動或手動載入更多，查閱較早紀錄。
4. 接收一則訊息，再重送最近事件：筆數只增加一次。
5. 切換離線、開啟自動接收，確認事件控制遵循連線狀態。

事件由本機來源產生；此作品沒有連線到正式 WebSocket。

## 先讀哪些程式

1. `src/app/App.jsx`：頁面與解析路由、lazy loading。
2. `src/features/commerce/domain/pricing.js`：共用費用規則。
3. `src/features/commerce/services/orderRepository.js`：重新驗庫存、訂單快照與寫入回復。
4. `src/features/operations/domain/orderWorkflow.js`：訂單狀態及匯出投影。
5. `src/features/business/domain/business.js`：合約與驗收驗證。
6. `src/features/messages/domain/messages.js`：訊息篩選、已讀和去重。
7. `tests/domain` 與 `tests/components`：從失敗情境理解規則與 UI 行為。

## GitHub 上傳前

- 建議儲存庫名 `david-shen-portfolio`，使用下載包最外層專案資料夾。
- 執行 `npm ci`、`npm test`、`npm run build`。
- 保留 `package-lock.json`；不要上傳 `node_modules`、個人環境變數、金鑰或瀏覽器儲存資料。
- 專案說明可寫：Bilingual React portfolio featuring e-commerce, operations, messaging and interactive product flows.
- 作品公開呈現實際參與背景與自主重建範圍，不把這份前端作品描述為前公司的正式系統。
